# REST API Use the REST API to retrieve BC Wildfire Service weather station information and weather data programmatically. ## On this page - [Overview](about-rest#overview) - [Getting started](about-rest#getting-started) - [Available endpoints](about-rest#available-endpoints) - [`/daily_weather`](about-rest#daily-weather) - [`/hourly_weather`](about-rest#hourly-weather) - [`/weather_stations`](about-rest#weather-stations) - [`/weather-stations/WEATHER_STATION_GUID/[station-id]`](about-rest#weather-stations-weather-station-guid-station-id) - [Pagination](about-rest#pagination) - [Sorting](about-rest#sorting) - [Searching and filtering](about-rest#searching-and-filtering) - [Date and time](about-rest#date-and-time) - [Response codes](about-rest#response-codes) - [OpenAPI specification](about-rest#openapi-specification) ## Overview The Weather DataMart REST API provides public access to BC Wildfire Service weather station information and weather data. Use the REST API to retrieve: - Daily weather data - Hourly weather observations - Weather station information ## Getting started ### Base URL `{{ applicationStateService.environment.REST_BASE_URL }}` ### Authentication The Weather DataMart REST API is publicly accessible and does not require authentication. No API key or access token is required. ### API version The REST API uses version 1 (v1). ### Request methods The API supports GET requests. It does not provide endpoints for other request methods. ### Supported formats Endpoints accept and return: - `application/json` - `application/xml` ## Available endpoints Endpoint | Description - | - `/daily_weather` | Retrieve daily weather data and fire weather indices. `/hourly_weather` | Retrieve hourly weather observations. `/weather_stations` | Retrieve weather station information. `/weather_stations/WEATHER_STATION_GUID/[station-id]` | Retrieve information for a specific weather station. All requests are **`GET`** ## Pagination The REST API uses pagination for endpoints that return large collections. This controlled by the `$first` and `$after` parameters in requests. Use the `$first` to specify how many records from result set to return per page. The default for this parameter is `100`, use `-1` retrieve all records. If the request has more records to return than the max specified by `$first`, then the result will contain an attribute called `nextLink`. Use the value in `nextLink` in the `$after` parameter to get the next page of results. ## Sorting Use the `$orderby` to specify the attribute and sort direction. For example: ?$orderby=STATION_CODE desc ### Sorting directions: - `asc` - ascending - `desc` - descending ## Searching and filtering Use the `$filter` paremeter to filter the result set of request. ### Comparison operators Operator | Description - | ------- `eq` | Equal to `ne` | Not equal to `lt` | Less than `le` | Less than or equal `gt` | Greater than `ge` | Greater than or equal `and` | Logical AND `or` | Logical OR `not` | Logical NOT `(...)` | Grouping ### Example: $filter=stationCode eq 790 or station_code eq 391 ### Quoted values Values containing whitespace or reserved characters must be enclosed in single quotation marks (`'`). Use a backslash (`\`) to escape quotation marks within a quoted value. To include a literal backslash, use two backslashes (`\\`). ### Examples Retrieve stations with an elevation greater than 100 metres GET /weather_stations?$filter=elevation_m gt 100 Retrieve daily data for stations 790 and 391 where the Buildup Index is between 100 and 150 GET /daily_weather?$filter=(STATION_CODE eq 790 or STATION_CODE eq 391) and BUILD_UP_INDEX gt 100 and BUILD_UP_INDEX lt 150 ## Date and time Date and time values use the standard ISO format: `YYYY-MM-DDThh:mm:ss` ### For example: 2022-12-31T23:00:00 This represents **December 31, 2022 at 23:00** Weather timestamps use Pacific Standard Time (PST), GMT−8, throughout the year and do not adjust for daylight saving time. Daily weather data is associated with the noon PST observation. For more information about date and time conventions, see [About weather data](about-weather-data). ## Response codes Code | Description - | -- `200` | Request successful. `400` | Bad request. ## OpenAPI specification An OpenAPI specification is available for developers: {{ applicationStateService.environment.REST_BASE_URL }}/openapi ## Related information - [About weather stations](about-weather-stations) - [About weather data](about-weather-data) - [GraphQL API documentation](about-graphql) - [Use the MCP server](about-mcp)
